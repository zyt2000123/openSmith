## 0. 最容易搞混的九组

先把最常被弄反的概念摆出来。

```mermaid
flowchart TD
    subgraph 一["Agent vs Identity"]
        A1["Agent：唯一运行实体<br/>只有一个 Smith"] -.->|"不是"| A2["Identity：能力档案<br/>可以有多个"]
    end
    subgraph 二["Route vs Pipeline"]
        B1["Route：意图声明<br/>可以没有 pipeline"] -.->|"不是"| B2["Pipeline：技能链<br/>被 route 引用"]
    end
    subgraph 三["Gate vs Guard"]
        C1["Gate：产出契约检查<br/>不过则重试"] -.->|"不是"| C2["Guard：安全边界<br/>不过则拒绝"]
    end
    subgraph 四["Session vs Run"]
        D1["Session：一串消息"] -.->|"不是"| D2["Run：一次执行"]
    end
    subgraph 五["Skill vs Tool"]
        E1["Skill：做事的方法论<br/>Markdown"] -.->|"不是"| E2["Tool：能力<br/>Python 函数"]
    end
```

| # | 容易混的一对 | 关键区别 |
|---|---|---|
| 1 | **Agent** vs **Identity** | Agent 只有一个（Smith）；Identity 是能力档案，可以有多个，切换 identity **不创建新 Agent** |
| 2 | **Route** vs **Pipeline** | Route 是意图声明（可以 `pipeline: null`）；Pipeline 是被引用的技能链 |
| 3 | **Gate** vs **Guard** | Gate 检查产出契约，不过就带反馈重试；Guard 检查安全，不过就拒绝 |
| 4 | **Session** vs **Run** | 一个 Session 有多个 Run；Run 才有状态机和 trace |
| 5 | **Skill** vs **Tool** | Skill 是"怎么做"（Markdown）；Tool 是"能做什么"（Python） |
| 6 | **FactGate** vs **ToolGuard** | FactGate 只挑战可重试可关闭；ToolGuard 不可绕过 |
| 7 | **trace** vs **summary** | trace 是逐事件原始记录；summary 是聚合投影 |
| 8 | **context.md** vs **durable.md** | 前者是用户协作偏好；后者是项目工作记忆 |
| 9 | **`recent.jsonl`** vs 记忆视图 | 前者是候选证据日志；后者是编译产物 |

## 1. 核心概念

### Agent

Smith 本身。**运行时唯一实体**，一个进程只有一个。有一份档案（`agent_profiles` 表 + `~/.agent-smith/agent/`）。

产品语言禁令：不说 "sub-agent"、"employee"、"digital employee"、"hire"。

- 代码锚点：`server/app/services/agent_profile_service.py`
- 详见：[01 · 总览](./01-总览.md) §3.2

### Identity（身份）

一份**能力档案**：角色提示 + 工具白名单 + 技能白名单 + 路由声明。目前两个：`smith`（默认）、`coding`。

`catalog.py` 的 docstring：

> 一个身份是唯一常驻 Smith agent 的一份能力档案。**它不是一个单独运行的 agent**，也从不拥有单独的服务端档案记录。

- 代码锚点：`agents/identities/*.yaml`、`engine/identity/catalog.py:IdentitySpec`
- schema：`agentsmith.identity/v1`
- 详见：[08 · Agents 内容层](./08-Agents-内容层.md) §3

### Route（路由）

身份内声明的一条意图：`id` / `keywords` / `examples` / `pipeline` / `priority`。

**`pipeline` 可以是 `null`**——`smith` 身份的 `git` 路由就是这样，它选中身份的工具和安全检查，但不进多步工作流。

评分：examples 命中 +10，keywords 命中 +3。排序键 `(score, priority, -声明顺序)`。

- 代码锚点：`engine/identity/catalog.py:RouteSpec` / `_score()`
- 详见：[08 · Agents 内容层](./08-Agents-内容层.md) §3.4

### RouteDecision

路由的完整结果：`identity` + `route_id` + `pipeline_id` + `score`。未命中任何路由时是 `RouteDecision(default, "direct", None)`。

- 代码锚点：`engine/identity/catalog.py:RouteDecision`

### Pipeline（管线）

一条声明式技能链。三条：`requirements-research`、`tdd-development`、`code-review`。

每个 step 有 `skill` / `gate` / `condition` / `allowed_tools` / `instructions` / `await_user_input_marker`。

- 代码锚点：`agents/pipelines/*.yaml`、`engine/execution/pipeline/pipeline.py`
- 详见：[02 · 快速上手](./02-快速上手.md) §14

### SkillChain

管线被解析后的运行时对象。节点数、门禁、条件都在这里。

- 代码锚点：`engine/execution/pipeline/skill_chain.py:SkillChain`

### Gate（门禁）

节点产出的**契约检查**。三态：`pass` / `retry` / `fail`。

- `retry` → 带 `retry_hint` 重跑本节点
- `fail` → 交给 `FailureLoopGuard`

20 个门禁：通用 5 个 + 编码 15 个。

- 代码锚点：`engine/execution/pipeline/gate.py:GateResult`、`agents/gates/*/gates.py`
- 详见：[04 · Engine 核心执行](./04-Engine-核心执行.md) §6.2

### LLMGate

两层门禁：**便宜的启发式预过滤 + LLM 语义验证**。输入上限 2000 字符，**两端各留一半**。

- 代码锚点：`engine/execution/pipeline/gate.py:LLMGate` / `_bounded_gate_output`
- 详见：[04 · Engine 核心执行](./04-Engine-核心执行.md) §6.3

### Condition（条件）

管线节点的执行条件。目前只有一个：`coding_bugfix_needs_diagnosis`。

- 代码锚点：`agents/conditions/coding.py:CONDITIONS`

### Skill（技能）

一个含**顶层 `SKILL.md`** 的目录，描述某类任务的工作方法。16 个（24 个目录里）。

- 代码锚点：`agents/skills/*/SKILL.md`、`engine/skill/registry.py`
- 详见：[08 · Agents 内容层](./08-Agents-内容层.md) §5

### Tool（工具）

一个定义了 **`TOOL_META` + `execute`** 的 Python 模块。19 个。没有基类、没有装饰器。

- 代码锚点：`agents/tools/*.py`、`engine/tool/registry.py`、`engine/tool/interface.py:ToolDefinition`
- 详见：[08 · Agents 内容层](./08-Agents-内容层.md) §4

### Hook（钩子）

工具生命周期三段：

| 类型 | 能阻断 | 能异步 | 返回 |
|---|---|---|---|
| `PreToolHook` | ✅ | ❌ | `(allowed, denial_reason)` |
| `PostToolHook` | ❌ | ✅ | `list[str]` 警告 |
| `StopHook` | ❌ | ✅ | — |

4 个内建：`config-protection`、`console-warn`、`quality-gate`、`cost-tracker`。

- 代码锚点：`engine/execution/hooks/tool/interface.py`、`agents/smith/hooks/`
- 详见：[08 · Agents 内容层](./08-Agents-内容层.md) §7

### Run（运行）

一次任务执行。有 `run_id`、7 态状态机、trace、summary，可中断可恢复。

状态：`QUEUED` / `RUNNING` / `WAITING_APPROVAL` / `COMPLETED` / `INCOMPLETE` / `FAILED` / `CANCELLED`。

- 代码锚点：`engine/execution/orchestration/run_state.py:RunStatus`
- 详见：[03 · 架构总览](./03-架构总览.md) §4

### Session（会话）

一串消息 + 上下文摘要 + 模型档案绑定。**一个 Session 包含多个 Run。**

- 代码锚点：`sessions` 表、`server/app/services/session_service.py`

## 2. 记忆

### Memory（记忆）

两份渲染视图，**整份注入 prompt**：

| 视图 | 路径 | 作用域 | 预算 | 章节 |
|---|---|---|---|---|
| `context.md` | `agent/context.md` | user | 4000 字符 | Confirmed Preferences / Collaboration Patterns / Stable User Context |
| `durable.md` | `agent/memory/durable.md` | project | 10000 字符 | Active Work / Pending / Verified Outcomes / Decisions / Known Pitfalls |

**没有 embedding、没有 FTS、没有 episodes、没有查询时检索。**

- 代码锚点：`engine/memory/MEMORY_POLICY.md` frontmatter
- 详见：[05 · 记忆系统](./05-记忆系统.md)

### `recent.jsonl`（证据日志）

**候选证据**的事件日志。不是记忆——写进去只表示"候选证据已记录"。保留窗口 7 天。

- 代码锚点：`engine/memory/store.py`

### ChangeSet（变更集）

记忆编译器的输出单位。**不是文档，是一组带证据的变更**（`add` / `remove` / `replace`）。

每条变更必须带 `evidence.ref`（真实事件时间戳）和 `evidence.quote`（原文片段）。

- 代码锚点：`engine/memory/_changeset.py:MemoryChange`
- 详见：[05 · 记忆系统](./05-记忆系统.md) §6

### 三道守卫（Adjudication）

代码在 Reviewer 之前**逐条**裁决变更：

| 守卫 | 问题 |
|---|---|
| **溯源**（Traceability） | 被引用的证据存在吗？新内容留在它之内吗？ |
| **保留**（Retention） | 这条 bullet 到底可不可以被删？ |
| **落位**（Placement） | 这个章节允许承载这种强度的断言吗？ |

10 个拒绝码。

- 代码锚点：`engine/memory/_guards.py:adjudicate()`
- 详见：[05 · 记忆系统](./05-记忆系统.md) §7

### 可证伪锚点（Falsifiable anchor）

内容里能被机械核对的片段：URL、反引号内容、带扩展名的路径（可带 `:行号`）、6 位以上数字。

**散文式表述没有锚点，交给 Reviewer。**

- 代码锚点：`engine/memory/_guards.py:_ANCHOR_PATTERNS`

### Dream

低频记忆卫生作业，每 50 次触发一次。**不产生新知识，也不改写记忆内容**：清洗密钥与注入，回收 `recent.jsonl` 的过期前缀。

- 代码锚点：`engine/memory/dream.py:run_dream()`
- 详见：[05 · 记忆系统](./05-记忆系统.md) §10

### Cleanup journal

`.dream_cleanup.json`。Dream 替换日志文件**之前**必须先写它（旧/新哈希 + 两个 offset），否则崩溃会让游标指过已下移的证据、静默跳过。

- 代码锚点：`engine/memory/dream.py:DreamCleanup`

### 编译游标

每个视图**各有一个**：`.compile_offset`（durable）、`.compile_offset_context`（context）。只推进到"本次真的送进 prompt 的那一条"。

- 详见：[05 · 记忆系统](./05-记忆系统.md) §9.3

### 四种编译终态

| 终态 | 含义 | 计入跳过计数 |
|---|---|---|
| `written` | 有变更写入 | — |
| `deferred` | 没有任何可应用变更 | **是**（连续 3 次则 `skipped`） |
| `rejected` | 草稿不安全或结构不合法 | 否 |
| `failed` | 供应商故障、超时、密钥失效 | 否 |

- 详见：[05 · 记忆系统](./05-记忆系统.md) §9.1

## 3. 执行

### ReAct 循环

核心执行循环：模型响应 → 工具调用 → 结果 → 下一轮，全在一条历史里。

预算：60 次有效迭代、20 次失败恢复、20 次事实门挑战、2 次假最终回答修复、2 次长度续写。

- 代码锚点：`engine/execution/react/react_loop.py:react_event_loop()`
- 详见：[04 · Engine 核心执行](./04-Engine-核心执行.md) §4

### ExecutionEvent

引擎产出的事件。26 种类型。`data` 是 `dict[str, Any]`。

- 代码锚点：`engine/execution/events.py:EventType`
- 详见：[03 · 架构总览](./03-架构总览.md) §3

### Provisional（试探性输出）

管线场景特有：节点输出**先流式渲染**，门禁不过要重跑时**从界面上撤回**。

三个事件：`PROVISIONAL_TEXT_DELTA` / `PROVISIONAL_COMMIT` / `PROVISIONAL_RETRACT`。

- 详见：[03 · 架构总览](./03-架构总览.md) §3.2、[11 · Shell 终端 UI](./11-Shell-终端UI.md) §5.3

### 假最终回答（Incomplete final）

模型调完工具后说一句"让我再查一下 X"就停了——这不是最终回答，是没兑现的承诺。用正则识别（长度上限 240 字符）。

- 代码锚点：`engine/execution/react/budget.py:looks_like_incomplete_final_after_tool()`

### PromptLayer

system prompt 的一层。16 层，每层带五个正交维度：`source` / `authority` / `trust` / `scope` / `load_reason`，外加 `trim_priority`。

- 代码锚点：`engine/context/assembler.py:PromptLayer`
- 详见：[04 · Engine 核心执行](./04-Engine-核心执行.md) §2

### 稳定前缀（Stable prefix）

从第 1 层开始**连续**、跨请求不变的那一段层。当前是第 1–10 层（第 11 层 `eval_guidance` 是易变的）。

**必须连续**，因为 provider 的 prompt 缓存按**字节前缀**匹配。

- 代码锚点：`engine/context/assembler.py:_stable_prefix()`

### `trim_priority`

层的裁剪优先级，**数字越小越先被裁**。`None` 表示永不裁剪（16 层里有 10 层是 `None`）。

裁剪顺序：`output_style`(10) → `durable_context`(19) → `skills`(30) → `tool_definitions`(35) → `toolbox_policy`(40) → `style`(50)。

### PromptManifest

一次装配的**脱敏收据**，可安全存进 trace：层名、来源、token 数、哈希，**不含内容**。

- 代码锚点：`engine/context/assembler.py:PromptManifest`

### 检查点（Checkpoint）

会话级的管线恢复点。两种恢复语义：

| 情形 | 从哪个节点继续 | 用户消息怎么用 |
|---|---|---|
| `awaiting_user_input` | **同一个**节点 | 作为 `user_response` |
| 崩溃恢复 | **下一个**节点 | 必须与原始请求逐字一致 |

- 代码锚点：`engine/execution/orchestration/agent_loop.py:_apply_session_checkpoint()`
- 详见：[03 · 架构总览](./03-架构总览.md) §6

### `FailureLoopGuard`

节点级失败升级：`retry`（第 1 次）→ `switch`（第 2 次）→ `blocked`（第 3 次）。**按 `error_type` 作键**，不按输出哈希（LLM 输出每次都变，永远不收敛）。

- 代码锚点：`engine/execution/pipeline/backtrack.py`

### `RuntimeContext` / `RuntimeServices` / `EngineRequest` / `EngineResult`

Engine 对外的四个数据契约（加 `ExecutionEvent` 共五个）。

- 代码锚点：`engine/execution/orchestration/runtime.py`
- 详见：[03 · 架构总览](./03-架构总览.md) §2

## 4. 安全

### ToolGuard

**不可绕过**的安全边界。1365 行。拦：路径攻击、31 条危险命令规则、平台完整性、敏感读。

- 代码锚点：`engine/safety/tool_guard.py`
- 详见：[06 · 安全与安全边界](./06-安全与安全边界.md) §3

### FactGate（事实门）

**只挑战不阻断**的行为纠偏：第一次编辑前必须先做只读调查。可用 `AGENT_SMITH_FACT_GATE` 关闭。

**必须排在 ToolGuard 之后**——有测试强制这个顺序。

- 代码锚点：`engine/safety/fact_gate.py`
- 详见：[06 · 安全与安全边界](./06-安全与安全边界.md) §7

### ToolPolicy

把 ToolGuard 和 FactGate 适配成同一个 `PolicyChecker` 协议，按顺序跑，第一个阻断者获胜。

**例外**：需要审批的决定被**延迟**，先跑完后面的检查器——因为"先去调查"优先于"打扰用户审批"。

- 代码锚点：`engine/safety/tool_policy.py:ToolPolicy.evaluate()`

### PermissionLevel

`read` → `write` → `execute` → `destructive`。策略链沿途取最高。

### RiskTier

`ROUTINE`(0) → `ELEVATED`(1) → `HIGH`(2) → `CRITICAL`(3)。

**决定缓存策略**：只有 `ELEVATED` 及以下能进会话白名单；`HIGH`/`CRITICAL` 每次重新授予。

- 代码锚点：`engine/safety/risk.py`

### ApprovalScope

用户看到并批准的**一次性能力**：`host_command` / `path` / `network` / `operation`。会被 `ToolRegistry` **再检查一遍**。

- 代码锚点：`engine/safety/approval.py:ApprovalScope`

### ApprovalBroker

审批的等待与解析。超时 300 秒。

- 代码锚点：`engine/safety/approval.py:ApprovalBroker`

### `boundary_block`

`GuardResult` 的一个字段：**唯一的问题是工作目录边界**。会话白名单可以放宽它，但高风险审批仍然可见。

### `declared_paths`

调用方**写的**路径拼法（绝对化但**不解析**）。因为 `resolve()` 会抹掉符号链接的名字，而守卫的目录成分规则按名字匹配。

**不进调用指纹**——它派生自 `arguments`。

- 代码锚点：`engine/tool/interface.py:ToolCall.declared_paths`

### 不可委派写根（Non-delegable write root）

Agent **不能写**的平台目录（`~/.agent-smith`），只有记忆目录下三个文件例外。

- 代码锚点：`engine/safety/tool_guard.py:_PLATFORM_DATA_ROOT`

### EvalGuard（评测敏感）

检测"这可能是一次评测/跑分"，注入一段禁止作弊的指引（prompt 第 11 层）。

- 代码锚点：`engine/safety/eval_guard.py`

### Seatbelt

macOS 的 `sandbox-exec` 沙箱。环境变量白名单只有 5 个。

**注意**：`engine/` 的 ~59 个跳过测试几乎全是 Seatbelt 测试，每个都带 `@pytest.mark.skipif(sys.platform != "darwin")`。

- 代码锚点：`engine/sandbox/macos_seatbelt.py`

### 审计哈希链（Hash chain）

防篡改追加日志：每条记录带 `seq` / `prev_hash` / `hash`。

**它做的是检测，不是防御**——能编辑日志的人同样能重写链条和锚点。

- 代码锚点：`common/hash_chain.py`
- 详见：[06 · 安全与安全边界](./06-安全与安全边界.md) §10

## 5. LLM

### LLMPort

**执行层唯一认识的模型接口**。实现者：`ProviderClient`、`RecordingLLM`、`ReplayLLM`、测试替身。

- 代码锚点：`engine/llm/port.py`

### ProviderAdapter

私有的适配器接缝，**只有 `ProviderClient` 消费**。实现者：`OpenAIAdapter`、`AnthropicAdapter`。

- 代码锚点：`engine/llm/adapters/base.py`

### LLMUsage（用途路由）

三条：`INTERACTIVE`（主对话）、`GATE`（门禁判定）、`BACKGROUND`（记忆编译、自动任务）。各有独立的模型配置与超时档。

- 代码锚点：`engine/llm/model_config.py:LLMUsage`

### 五层配置合并

环境变量 → 平台 `~/.agent-smith/config.yaml` → Smith 种子 `agents/smith/config.yaml` → Smith 运行时 `~/.agent-smith/agent/config.yaml` → 会话覆盖。**下层覆盖上层。**

`None` 表示"不表态"，不覆盖下层。

- 代码锚点：`engine/llm/model_config.py:resolve_llm_config()`
- 详见：[02 · 快速上手](./02-快速上手.md) §3.1

### `*_declared`

`ModelLimits` 上的布尔字段：区分"模型声明了这个值"和"没声明所以我用了默认值"。

同类设计：`usage.py` 的 `usage_reported`、`health.py` 的 `tool_success_rate=None`。

### `prefix_cache_key`

传给 provider 的缓存提示。**默认能力为 `False`**——只有声明支持的 adapter 才会收到它。

绑定的是**裁剪之后实际渲染**的稳定前缀。

### GenerationRecord

每次模型调用一条记账记录：`purpose` / `usage` / `ttft_ms` / `total_ms` / `stream` / `ok` / `source_key`。

**记录严格尽力而为**：sink 失败绝不影响模型调用。

- 代码锚点：`engine/llm/observability.py`

### `vendor`

供应商**显示名**。只能写在顶层，不进路由覆盖，不进 adapter 请求，但会进运行时 prompt 元数据（让"你是什么模型"有诚实答案）。

**算客户端缓存指纹时被显式剔除。**

---

## 6. 可观测

### trace

一次 run 的**逐事件 JSONL**，带哈希链。两层脱敏（按键名 + 按值内容）、有界（4096 字符 / 4 层 / 100 项）。

- 代码锚点：`engine/observability/trace_store.py`

### summary

一次 run 的**聚合投影**：事件计数、工具调用数、回退数、token 用量、终态。**不保留原始载荷。**

- 代码锚点：`engine/observability/projections.py:RunSummary`

### Incident（事故）

确定性分类的运行失败：`budget_exhausted` / `tool_timeout` / `repeated_backtracks` / `run_failed` / `trace_integrity`。每个带 `evidence`。

- 代码锚点：`engine/observability/incidents.py:RunIncident`

### Diagnosis（诊断）

根因分析。取**最具体**的事故作主因（优先级 `tool_timeout` 0 < `budget_exhausted` 1 < `run_failed` 2）。

**提议变更但从不应用。**

- 代码锚点：`engine/observability/diagnosis.py:RunDiagnosis`

### ImprovementProposal（改进建议）

由诊断产出的保守建议，**永远需要审批**。`trace_integrity` 类不产出建议（trace 被动过时任何结论都不可信）。

**优先建议行为改动而非放宽参数**：预算耗尽的建议是"减少重复调用"而不是"调高上限"。

- 代码锚点：`engine/observability/proposals.py`

### AgentHealth（健康度）

运行窗口的聚合指标。工具成功率**排除三类**：门禁探针、被拒审批、超时审批。

没有工具调用时 `tool_success_rate` 是 `None` 而不是 `0.0`。

- 代码锚点：`engine/observability/health.py`

### 保留策略

三条独立的界：2000 次完成运行 / 90 天 / 512 MB。环境变量可覆盖，**`0` 表示禁用该条**。

- 代码锚点：`engine/observability/index.py:ObservabilityRetentionPolicy`

## 7. MCP

### MCP（Model Context Protocol）

外部工具协议。声明版本 `2025-11-25`，接受 4 个版本。

### 两种传输

`StdioMCPTransport`（子进程逐行 JSON-RPC）、`StreamableHTTPMCPTransport`（HTTP + SSE）。

### 四道边界

单消息 1 MB / 整流 64 MB / 请求墙钟 600 秒 / 工具列表 100 页。

**墙钟是必需的第四道**：前三道拦不住"涓流"，因为涓流恰恰不花字节。

- 详见：[12 · MCP 集成](./12-MCP-集成.md) §4

### `framing_broken`

stdio 传输超限后的**永久报废**标记。逐行 JSON-RPC 没有帧长度前缀，中途放弃读取会让流永久失同步。

## 8. 基础设施

### `AppPaths`

运行时数据根的**唯一真相源**。`0o700` 目录 / `0o600` 文件，逐段拒绝软链，项目根需通过三文件签名校验。

- 代码锚点：`common/paths.py`

### `merge_configs`

通用深合并。**`None` 不覆盖**——这一行撑起了整个五层配置合并。

注意区分：通用合并算法在 `common/`，"哪五层、什么优先级"在 `engine/llm/`。

- 代码锚点：`common/yaml_utils.py:merge_configs()`

### 内建技能镜像

`agents/skills/` → `~/.agent-smith/builtin/skills/`。增量同步（元数据 → SHA-256 → 复制三级判定），带空源防呆。

`agent/skills/` 留给**用户安装**的技能。

- 代码锚点：`common/paths.py:_install_builtin_skills()`

## 9. Shell

### `Static`

Ink 的组件：把内容**一次性写进 scrollback**，之后不再重绘。已完成的会话记录必须走它。

**陷阱**：全屏面板卸载再挂载 `Static` 会把整卷历史重印一遍。修法是 epoch + `clearTerminal()`。

- 代码锚点：`shell/src/index.tsx`

### `transcriptEpoch`

强制 `Static` 认为内容是全新的计数器。用在 `/clear`、`/new`、`/resume` 和全屏面板切换四条路径。

### SkillState

技能块的七个状态：`running` / `retry` / `waiting` / `done` / `blocked` / `error` / `cancelled`。

`retry`、`waiting`、`blocked` 三个在没有门禁和管线的终端里没有对应物。

- 代码锚点：`shell/src/transcript-state.ts`

### nonce / stale

`/api/health` 的两个字段：

- `nonce` 回显 `SMITH_SERVER_NONCE`，让 Shell 分辨"这个 server 是不是我拉起来的"
- `stale` 报告"我跑的代码比工作树旧"

**`stale` 缺失等同于 `stale=true`**——最陈旧的后端最不可能报告自己陈旧。

- 代码锚点：`server/app/main.py`、`shell/src/dev-server.ts`

## 10. 项目约定

### "按消费方的判定标准计数"

不按目录列表数。技能算不算取决于有没有顶层 `SKILL.md`（24 个目录 → 16 个技能）；工具算不算取决于有没有 `TOOL_META` + `execute`。

- 出处：`CLAUDE.md` 开头

### "Trust code over docs"

`docs/` 根目录那套没有随重构同步。代码与文档冲突时以代码为准，**并修文档**。

本 wiki 目录（`docs/wiki/`）就是按这条重写的。

### 产品语言

**用**："Smith"、"Agent"、"skill"、"session"、"memory"、"tool"、"template"

**不用**："sub-agent"、"employee"、"digital employee"、"hire"

### `SMITH_TEMPLATE_ID` / `personal-assistant`

遗留兼容 id。老的 API 路径和数据路径还在用，改它会破坏已有安装的数据定位。

- 代码锚点：`engine/llm/model_config.py`、`agents/smith/config.yaml` 的 `role:`

### 未实现（明确记录）

| 项 | 状态 |
|---|---|

| 查询时记忆检索 | 未实现且不打算实现 |

## 11. 反复出现的设计模式

这套代码库里有若干模式在多个子系统独立出现，值得单独列出来。

| 模式 | 出现处 |
|---|---|
| **两端各留一半 + 显式标注中间省略** | 门禁输入 `_bounded_gate_output`、记忆 `_truncate_source`、宿主输出 `host.py` |
| **区分"没数据"与"值为零"** | `usage_reported`、`*_declared`、`tool_success_rate=None` |
| **`bool` 是 `int` 子类，必须显式排除** | `usage.py._number()`、`dream.py._load_dream_cleanup()`、`catalog.py` 的 `priority` |
| **未知字段一律报错** | 身份 YAML、技能设置 YAML |
| **运行时宽容，启动时严格** | 技能缺失降级 + `validate_execution_assets()` |
| **环境变量宽容，代码构造严格** | `ObservabilityRetentionPolicy` |
| **fail-closed** | 工具白名单、路径根发现、记忆守卫、checkpoint 所有权判定 |
| **正则边界断言是承重的** | 路由 `_keyword_hit` 的 ASCII lookaround、记忆锚点的 `\b`、trace 密钥的前置边界 |
| **进程组信号而非单进程** | Shell 拉起 uvicorn、宿主命令执行 |
| **必须手工同步的多份副本** | 凭据清单（3 处）、token 键白名单（2 处）、私钥正则（2 处） |
