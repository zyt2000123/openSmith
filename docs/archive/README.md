# docs/archive · 已取代的旧稿

## 这里的文档不是当前事实

本目录保留被后续文档取代的实现说明。它们**不再随代码更新**，读它们只为一个目的：
追溯当时为什么那样设计。任何与正本或源码冲突的地方，以正本和源码为准。

每篇开头都有一条取代声明，写明接替它的正本**和裁决依据**。

## 裁决是怎么做的

不比篇幅，不凭“新的应该更好”的直觉。做法是：从当前源码测出一组可核实的事实
（工具数、端点数、提示词层数、危险规则条数、某个子系统的关键机制是否被正确描述……），
再拿这组事实逐条查两篇候选，谁命中得多谁是正本。**平局才取更新的一篇**——写错的详尽
不如写对的简洁，而文档随代码腐烂，新的漂移时间更短。

最有鉴别力的一类探针是**它怎么描述被删掉的东西**。照着现有代码描述现状人人都会；
只有真正跟着代码走过一遍的文档，才会专门写一章讲“我们删了 episodes，因为它需要检索，
而检索被否决了”。删除记录是文档与代码同步过的不可伪造的证据。

## 为什么保留而不是删除

`docs/README.md` 维护规则第 3 条：不删除有决策价值的旧稿。删掉的话，“当初为什么不
那么做”就只能靠翻 git 历史回答了；而归档件里往往还留着正本没有的取舍记录。

## 什么时候该往这里加东西

当两篇现行文档开始描述同一件事时。判据不是“旧”，是**重复**——重复会让读者在两个
说法之间猜，而猜错的代价由代码承担。按上面的裁决方法定出正本，把落败的那篇移进来，
写清取代者与依据，并把指向它的链接改到正本。
