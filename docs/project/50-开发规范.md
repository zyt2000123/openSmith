# 10 · 开发规范与约定

> **适用范围**：本仓库的 Python Engine/Server 与 TypeScript Shell。代码和测试优先于本文；本文记录跨模块约定与可重复的开发入口。

## 分层与依赖

```text
shell ──HTTP/SSE──> server ──> engine ──> common
                         │        ▲
                         └─ loads agents/
```

- `common/` 不依赖业务层；
- `engine/` 不依赖 FastAPI、Shell 或数据库 repository；
- `server/` 负责 HTTP、持久化和运行时装配，不复制 Engine 的 LLM/安全/执行逻辑；
- `shell/` 仅通过 API 与 Server 通信，不根据展示文字反推 Run/审批事实；
- `agents/` 是声明性身份、技能、pipeline、gate 和 provider 内容，不能私自绕过 Engine 的 registry 与安全边界。

## 本地开发

前置条件：Python 3.11+、`uv`、Node.js 22+。

```bash
# 安装 Python 包
cd common && uv sync
cd ../engine && uv sync --extra test
cd ../server && uv sync --extra dev

# 安装 Shell（dist/ 已被 gitignore，仅 npm ci 跑不起 smith）
cd ../shell && npm ci && npm run build && npm link
```

通常从仓库根运行 `smith`；本地开发中 Shell 会负责检查/启动本地 Server。需要单独调试后端时：

```bash
cd server
uv run uvicorn app.main:app --reload
```

模型配置应优先通过 Shell setup、`/config` 或本地配置 API 写入。不要把真实 API key、token 或私有 URL 提交到 YAML、测试快照或文档。

## 质量命令

在改动相应层后执行：

| 改动范围 | 命令 |
| --- | --- |
| Engine | `cd engine && uv run --extra test pytest tests` |
| Server | `cd server && uv run --extra dev pytest tests` |
| Shell | `cd shell && npm test && npm run check` |
| Shell 发布内容 | `cd shell && npm run build && npm pack --dry-run` |

本表定义 Python 测试命令的权威写法（`--extra test` / `--extra dev`）；CLAUDE.md
与 `.githooks/pre-push` 使用的 `uv run --with pytest --with pytest-asyncio pytest`
是等价替代写法。仓库没有 pytest 配置文件，两种写法运行同一套测试。

自动触发点只有一个：`.githooks/pre-push`（本项目不引入 CI）。启用方式
`git config core.hooksPath .githooks`，它在推送前跑 engine + server 两层完整测试，
不含 shell——shell 改动需手动 `cd shell && npm test`。

Shell 有一处已知的环境性失败：在没有 `~/.agent-smith/auth_token` 的容器中，
12 个 auth 相关测试必然失败；规避方式见 CLAUDE.md §9。

需要快速定位时先跑受影响测试；合并前应运行该层完整命令。若测试未运行、环境缺少模型凭据或结果失败，交付说明必须如实写出，不能用“理论上通过”替代结果。

## 代码与提交纪律

1. 保持提交聚焦。不要把重构、依赖升级、格式化全仓和行为变更混入一个难以审查的提交。
2. 所有路径输入必须先归一化并受工作目录边界保护；不得假设 macOS/Linux 的大小写、符号链接或 Git worktree 行为相同。
3. 不可信文本（文件、网页、工具、模型输出）不能被当作指令、权限或 shell 参数；呈现和执行之间必须经过显式契约。
4. 添加或改变持久化字段时考虑旧文件、未完成 Run 和升级回滚；不可恢复删除必须有明确授权。
5. 使用 Conventional Commit 风格，例如 `feat(engine): add …`、`fix(shell): …`、`docs: …`、`test(server): …`。
